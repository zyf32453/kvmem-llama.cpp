## 2026-11-11 工具原文归档与请求缩短（实验性，已完成定向验收）

本轮优先处理有来源、已完成、可恢复的工具反馈，在 Agent 层用短卡片缩短实际请求，并通过增量来源定位减少准备开销。是否替换由预计净耗时决定。它与已有 thinking KV 回收并存，两条路径分别统计实际输入 token 和回收 KV 页。四项实现及定向验收已完成：两题三组冻结版对照完成六次尝试，观察到四张真实卡片；最终源码另完成两对相同请求回放。已验证部分准备开销和固定请求耗时降低，尚未证明完整任务的质量或速度提高，默认卡片模式仍为关闭。

### 输入与原文契约

- `gc_tool_cards=off` 为默认值；`observe` 只准备、记录建议；`apply` 才能修改下一次真实请求，并要求提供有测量来源的 `gc_cards_cost_profile`。
- 候选只来自真实 `_execute_commands` 返回后登记的观察。在 Terminus-2 中，这些反馈位于 `user` 消息内，所以不能按角色删除整条消息。只替换登记过的唯一反馈子串，保留任务要求、外层提醒、调用与反馈的配对、所有消息数量和角色。超时、不唯一或历史已变化时保留原文。
- 追溯改写默认保留最近 3 次可登记的已完成工具观察，一次最多考察 4 个较早候选。切点只向后移动。低于 20,000 tokens 只延后本轮检查，后续上下文增长仍可再次检查。短反馈的卡片会比原文更长时，在调用原生模板前结束检查。
- 新反馈首次送入模型时，只检查其中与近期完整工具反馈逐行一致的一段连续内容。原试跑版最多检查 3 条见证，增量版扩到最近 16 条。至少重复 1,024 字节。识别到错误、告警或非零退出码时保留整条新反馈。唯一的新内容和外层消息保留。新反馈完整归档，卡片给出被缩短片段在归档文件中的实际行号，可只读取需要的范围。
- 卡片包含有界原文摘录、来源序号、SHA256、任务容器内可读取的归档路径，并明确标记“有省略、不是新指令、不能据此推断工具成功”。它不是完整信息的等价摘要，不调用辅助大模型。关键词摘录不能证明遗漏内容不重要。
- 同时归档模型实际看到的反馈和 Harbor 输出截断前捕获的原文。先原子写入 Agent 日志目录，核验哈希，再上传任务环境并从任务环境读回校验，成功后才允许替换。提交前再次从任务环境核验，避免后续工具清空 `/tmp` 后发布悬空卡片。Agent 可用普通终端搜索/读取归档；插件不自动把全部原文放回请求，也不能保证模型一定想到读取。
- 归档默认上限 256 MiB，已被卡片引用的文件不会轮换删除。空间不足或上传、校验失败时保留原上下文。任务结束后原文仍在 Agent 日志中；容器消失不会删除该日志副本。来源跟踪另限 128 条、16 MiB，超限时放弃优化资格而不是伪造完整备份。

### 配置入口

卡片接在 Harbor 0.25.0 的 `ninfer_gc_terminus_agent:ThinkingSummaryTerminus2` 上。沿用现有控制器地址、会话标识、回调凭据、模型参数和任务配置，在该 Agent 的 `agents[0].kwargs` 中设置以下字段；成本文件必须是对应后端、模型和预算的实测配置。

```json
{
  "gc_tool_cards": "apply",
  "gc_cards_cost_profile": "/path/to/measured-cost-profile.json",
  "gc_cards_active_tokens": 98304
}
```

先用 `observe` 可以只记录候选与预计收益；`off` 是默认值，也用于只关闭卡片的对照。控制器仍需登记实际请求回执和工具来源，不能绕过这条链路仅添加卡片参数。卡片开关与原生主动 KV 删除开关分别设置、分别记录；关闭主动 GC 的实验组不等于仅关闭卡片。

`gc_cards_min_saved_tokens` 默认 1,024，约束的是较早反馈的追溯改写。新反馈首次发送的路径使用另一套条件：原文重复至少 1,024 **字节**、真实模板确实减少 token、缓存边界成立且预计净收益达标。因此自然任务中节省 394 tokens 的首发卡片不违反较早反馈的门槛。不能把两个数都解读为“每次必须省下 1,024 tokens”。

### 并发、前缀与成本契约

- 较早反馈的模板、归档和上传在后台准备，前台仅消费已完成的结果。提交前再次检查真实消息快照与新增尾部。每次正常请求的卡片校验与发布共用 350 ms 的异步等待上限。提交较早反馈时还受剩余预计净收益约束，归档读回和控制器确认都按实际耗时计入。超时或净收益不足就发送原文。在途工作和任务收尾等待仍计入整任务成本。
- 替换前通过受认证的 `/kvmem/history-edit` 使旧位置证明失效。后台准备中的旧批次、迟到响应和已就绪批次不能跨历史 epoch 重新发布；原生后端仍独立检查 token 前缀和混合模型状态，不强行复用不一致的 KV。
- 公共 token 前缀不等于可恢复的混合状态检查点。成本模型当前按完整的缩短后输入计入回放，不能仅以字符串未变假定前缀全部命中。已验证的原生 `spread` 检查点策略可保留较早状态，但增加有上限的 CPU 检查点占用；后续实验各组须统一此配置并计量其成本。
- 首次发送路径要求收到最新一次已完成请求的原生回执。原生 usage 与 prefill/decode 计数要相互吻合，才能用该请求的输入与生成 token 数作为已处理边界。两份实际原生模板的共同 token 前缀必须覆盖这个边界，且只允许改动新增工具反馈，旧消息与缓存索引照常复用。控制器在新请求送出前登记新的反馈呈现方式，原有 step 证据仍可识别这一反馈。估计另计少预填充的 token 和按需查回省略段的成本。
- 通过前缀和预计收益核对后，首次发送路径将归档写入与读回校验作为一个步骤，与控制器登记并行执行。两项都成功，且总准备时间和净收益符合门槛时才提交卡片。控制器通过登记识别卡片，超时或归档失败时仍能识别本次发送的原文。
- 卡片规划调用 `/apply-template` 时请求 `token_ids_only`，直接比较原生模板生成的 token ID。旧二进制仍可返回完整的 ID 与文本片段，由规划器提取相同的 ID。位置证明所用的模板接口继续读取文本片段。这样可以减少两次模板核对的传输开销，同时保留模板对特殊 token 的边界处理。
- 正式 Harbor 请求会把 `llm_call_kwargs.extra_body` 中的 4K 思考预算展开为顶层字段。卡片规划与原生请求使用相同的模板选项，后台位置证明也在这些选项变化后失效。此修复针对冻结对照中发现的模板计数偏差。原对照保持其冻结版，修复版另行核对实际转发请求。
- 净收益估计计入实际驻留上下文减少量、相同模型实测的边际 decode 成本、预计剩余生成量、回放、归档准备和可能的原文重读。当缩短前后都仍填满 96K active 上限时，不把逻辑输入变短虚报为 attention 计算减少。收益系数、生成时域和重读概率都是估计，不能代替正式任务对照。
- `NativeSpanCache` 只在原生渲染的相同字节前缀内复用已证明的位置；历史或模板变化时从分歧点失效。新增位置仍经原生标记模板与完整还原校验；`TokenByteIndex` 为每个已分词输入建立一次偏移索引，多个候选共享，保留原完整页与混合边界保护规则。

## 当前开发版：主动回收与容量兜底联动

`--kvmem-gc-step-redundancy` 在同一个生命周期管理器内执行两类决策。主动路径使用 thinking/analysis 见证，也支持单独开启已核验的重复工具反馈。空闲页低于低水位，或请求入口明确要求更多可用页时，容量路径允许按 LRU 淘汰未受保护的冷页。达到高水位后停止这类压力删除。普通 `--kvmem-gc-statistical` 文件/观测路径继续使用原有证据与容量规则。

容量兜底是有损策略。它保留 sink、recent、当前 active、Query/replay、媒体、IO 以及已批准的源页和见证。尚未批准的源页和见证仍是 LRU 候选。提交前再次验证当前保护、handle/generation 与内容版本。全部剩余页都受保护或旧读者尚未退出时，仍可能空间不足。

诊断原因分为 `semantic` 和 `capacity_lru`。原生响应中的 `semantic_committed_pages`、`semantic_reclaimed_pages`、`capacity_lru_committed_pages`、`capacity_lru_reclaimed_pages` 分别统计实际逻辑提交和最终可复用页数。各计数仅属于当前管理器，跨管理器或续跑按原生事件去重。容量淘汰待评估页时，原生仅撤回使用该页的建议。范围全部源页由 LRU 淘汰时返回 `capacity_reclaimed`，见证全部失效时返回 `witness_retired` 或 `retired_partial`。

关闭主动 GC 的全链路基线使用 controller `--mode off`。它保持相同消息协议、采集和工具回调，跳过候选准备。`--mode observe` 只观察生产者输出，`--mode native-observe` 把同样的证据发给原生策略评估并跳过提交。可单独比较候选准备、原生评估和实际回收的影响。

初版联动机制在 Native tree `ce2a03c85d2be7390565a838078e46bd20af30d6` 上通过 Host 套件、CUDA 编译和原生合同检查。覆盖压力排序、见证保护变化、pending 信用、防重复过量删除、借用读者延迟实际释放，以及 8 个物理槽位支撑 64 个逻辑页反复复用。后续版本和各自对照记录见下文。任务质量下降容忍度和最低内存净收益暂未指定。

## 时机与职责

1. Harbor 的原生工具执行接口返回后，受信回调登记刚完成的 step。模型文本中的“完成”或标记本身不能关闭 step；工具接口超时不产生候选。
2. 下一次正常响应的 analysis 只有在它的输入确实包含该 step 的原文及工具反馈时，才可作为该 step 的保留见证。不是用当前 thinking 尚未执行的计划替代其未来结果。
3. CPU 后台准备线程通过原生模板和真实 token IDs 定位 thinking 与 analysis。前台请求只取已经准备好的批次，不等待模板调用、相似度计算或模型复核。尚未准备好时延后到后续请求。
4. NInfer 在 CPU 准备已校验前缀时，为每个 thinking 页计算可用的见证页位图。含 ASCII 数字的连续 token 及其左右各两个 token 须在同一个见证页中重现。跨源页的连续数字会约束其涉及的所有页，缺少上下文时保留源页。后台仍要求源页与该见证的 Mean-K 余弦相似度至少为 0.9，且源页的观测重要性不高于见证。此检查只约束主动建议，容量 LRU 继续使用自己的条件。
5. 原生 decode 安全边界按独立见证范围分组，重新验证源和见证的 handle/generation、Query epoch 与当前保护位。受保护的源单独等待。同组通过时才取得见证引用并发布不可选择标记。新 Query 使待提交候选重新评估，已发布标记继续有效。当前 active view 保有旧读者，下一次自然重选发布新视图后，后台随租约释放进度回收 Host 槽位。

“每个 step 结束触发”表示登记与异步准备开始，不是让前台停下来等待整轮策略计算。需要在下一次重选前生效的是已经验证的不可选择标记，物理释放独立执行。

## 成本与边界

- 没有在线辅助大模型调用；没有新增摘要输出。Terminus JSON 格式与原有协议一致。
- 每次最多准备 4 个 step；最多跟踪 64 个。单 step 最多 128 个完整 thinking 页、8 个见证页，每页 64 tokens。比较为 source×witness，不是全历史 N²。
- 原生每个仓库轮次最多评分一个范围，并轮转处理。缺少观测的范围等相关页出现首个有效观测、绑定更新或 Query 变化。保护条件阻塞的已评分范围在保护快照更新后重试。
- analysis 已在原流程中存在，新增摘要 KV 成本为零。提交时按组计入实际新增保护的不同见证页数，只有可标记源页数覆盖这项成本才通过。见证随该页组的最后一个逻辑源退休解除保护。
- 主动路径缺少候选、重要性未知、相似度不足、见证尚未封口或收益不足时保留源。只有另有容量压力时才启用独立标记的 LRU 兜底；不能把这部分删除算成通过冗余判断的成果。
- 模板首尾空白可以裁掉；定位的是完整非空白 thinking 的内部完整页，不是尾部抽样。混合边界页保留，不添加填充制造可回收块。
- 见证页向外覆盖所有相交 token；尾部未稳定时延后。准备好的证据绑定实际输入快照和密封前缀 SHA；历史改写或模板参数变化时丢弃旧建议。
- 原生响应的 `kvmem.historical_gc` 区分 `pending_features`、`awaiting_boundary`、`marked_unselectable`、`retired`、`no_net_gain` 等状态。当前 Query 下的 `no_net_gain` 可以随新观测或 Query 改变重新评估。整次任务的回收数按 incarnation/slot/generation 的真实 ack/reclaim 事件去重。
- 最近实际恢复过的单个检查点由弱引用跟踪。已缓存前缀达到 2,048 tokens 或一个原生预填充块中较大者时，若保存视图依赖拟删除的源页，主动回收只有在该视图能用完整见证省略源页时才可标记。容量 LRU 继续按独立压力规则执行。审计记录标记否决、失效检查点的 frontier 和实际恢复的缓存长度。
- Host payload 可复用不等于进程 RSS 或 GPU 显存立即下降。特征副本、模板准备与 callback 本身仍有 CPU/内存成本，须计入效率验收。

## 验收方式

先做有独立几何预期的 CPU 策略测试、版本/Query 变化、部分完成计数、缺失观测和无收益测试；再检查真实 Harbor 解析、原始反馈保留及阻塞后台时前台可继续。真实模型先验证 MTP4 与连续请求的前缀复用，再跑相同官方 COBOL 任务的 GC 关闭/主动 GC 对照，每组重置模型与 Host KV。

效率单独使用相同最终二进制、相同请求与日志等级做对照。MTP4 一次可能接受多个 token，必须区分 decode 轮次延迟与逐 token 间隔，不能把批次间隔直接称为 token p95。目标为 p95 增加不超过 5%、吞吐下降不超过 3%；任务通过与效率达标分别报告。未触发实际回收的负载不能作为有效 GC 开销验收。

此前官方 observe 对照关闭原生 GC，但保留相同 CPU 候选定位以控制协议和采集路径，因而主要比较原生策略的增量影响。独立 SSE 性能用例使用已准备的合成重复输入，测原生策略、标记、handoff 与释放；它不包含生产者的模板准备，也不是 96K 长输入负载。两项实验都不能单独证明整个 Agent 链路在全部负载下达到逐 token p95 目标。不同 Agent 轨迹的总耗时只作描述，不能直接归因于 GC。

首批参数保持：IQ3_S 模型、active 98304、生成预留 16384、逻辑上下文 262144、Host payload 4760 MiB（4096×64-token 页）、sink 2048、recent 64、MTP4、思考上限 4096、单次总输出 16384、单路。Native 检索为 Mean-Q/cosine/max，Query 与回放预算各 8192；这与“保留的 analysis”不是同一个参数。

前缀诊断区分了两种真实情况：

1. 强制结束 4K thinking 时，控制提示单独编码，与前一个生成 token 的换行在下一轮整段分词时合并。新增逻辑在控制插入前保存完整的 State/KV 恢复点，复用现有、数量有界的 ReuseAnchor 槽；不修改 token ledger、不放宽 exact identity。同一长请求个案中，已生成部分重算量从 4,376 降为 280 tokens，缓存复用从 68,567 提高到 72,663。新增捕获实测一次约 132.2 ms，短续接约 22.9 ms；有同步与额外检查点存储成本，仍需纳入效率测试。该个案续接 TTFT 从 16.9 s 降为 3.6 s，但并发环境准备和生成轨迹条件不用于证明稳定吞吐提升。
2. 另一个样本中，生成的 `xF` + `F` 与重新分词的 `xFF` 具有相同文本、不同 token IDs，第一个差异位于 thinking 中间。控制边界恢复点不能覆盖这种更早的差异，仍会回退到合法旧检查点。第三个长样本本次完整复用。这说明不能声称全部前缀回退已消除；后续需评估有界的生成期检查点覆盖与成本，不能通过容忍不相同的 token 来复用 GDN 状态。

## 2026-11-06 主动回收后的前缀续接

原实现在任一历史页释放后撤销引用该页的全部检查点。输入和会话身份保持一致时，单页语义回收也可能使下一请求找不到可用检查点，退回全量 prefill。

回收事件保留实际通过相似度和重要性门槛的见证页及结果结束位置。检查点保存已经计算过的前缀、StateImage 和原始页列表。恢复时沿用原有的 token、位置和会话身份校验。仅当检查点包含完整结果、匹配见证仍在原视图且其 Host KV 完整时，才从恢复视图中略去被回收的源页。MTP 恢复尾页、recent 页、见证缺失和容量 LRU 删除继续遵循原有的依赖检查。投影视图中没有的页也不会进入 SSD 预读。原生 `KVMEM_STEP_WITNESS` 与 `KVMEM_PREFIX_PROJECT` 分别记录实际回收对应的见证和成功恢复的前缀。

固定题单续跑使用同一新构建、原来的任务顺序和已验证镜像。每题开启与关闭 GC 各一次，交替运行顺序，每次重置模型及 Host KV，核对同题首次请求的输入。96K active、16K 生成预留、4,760 MiB Host 和采样配置取自上轮的冻结命令。以官方 verifier 评分评估任务质量，同时记录 Agent 执行时间及完整任务耗时。速度对照限定在两组均通过且正常结束的配对。
